## 1. ОБЩЕЕ ОПИСАНИЕ ПРОДУКТА

### 1.1. Что такое SkillFlow

**SkillFlow** — это веб-платформа с Telegram-ботом, которая позволяет студентам университета создавать учебные тесты друг для друга, проходить их и соревноваться в рейтинге по дисциплинам.

**Простыми словами:** Студент создаёт тест по предмету → другие студенты проходят → все видят рейтинг → лучшие получают достижения.

### 1.2. Что система делает (конкретно)

| Функция | Как работает |
|---------|--------------|
| **Создание тестов** | Студент заходит на сайт, нажимает «Создать тест», вводит вопросы с вариантами ответов, отправляет на проверку преподавателю |
| **Прохождение тестов** | Студент выбирает тест из каталога, отвечает на вопросы, сразу видит результат и сколько баллов рейтинга получил |
| **Модерация** | Преподаватель видит список тестов на проверке, одобряет или отклоняет, после одобрения тест появляется в каталоге |
| **Рейтинг** | После каждого пройденного теста баллы добавляются в таблицу лидеров по предмету |
| **Достижения** | Система автоматически выдаёт бейджи за успехи (первый тест, серия побед, топ-3 в предмете) |
| **Telegram-доступ** | Можно пройти тест и посмотреть рейтинг прямо в боте, не заходя на сайт |

## 3. ФУНКЦИОНАЛЬНЫЕ ВОЗМОЖНОСТИ (ПОДРОБНО)

### 3.1. Модуль аутентификации

**Что происходит:**
1. Пользователь открывает главную страницу
2. Нажимает «Войти» или «Регистрация»
3. Вводит email и пароль
4. Система проверяет данные в базе
5. При успехе — перенаправляет в личный кабинет, выдаёт JWT-токен
6. При ошибке — показывает сообщение «Неверный email или пароль»

**Telegram-привязка:**
1. В личном кабинете пользователь нажимает «Привязать Telegram»
2. Система показывает 6-значный код
3. Пользователь пишет код боту @SkillFlowBot
4. Бот привязывает Telegram ID к аккаунту
5. Теперь бот знает, кто пользователь, и может показывать персональные данные

**Технические детали:**
- Пароли хранятся в хэшированном виде (bcrypt)
- JWT-токен действует 24 часа
- После выхода токен аннулируется

---

### 3.2. Модуль создания тестов

**Что происходит:**
1. Студент нажимает «Создать тест»
2. Заполняет поля: название, описание, предмет (выбор из списка), сложность (1–5)
3. Добавляет вопросы (минимум 3, максимум 50)
4. Для каждого вопроса указывает:
   - Тип (одиночный выбор / множественный выбор)
   - Текст вопроса
   - Варианты ответов (от 2 до 10)
   - Отмечает правильные варианты
   - Баллы за вопрос (1–10)
5. Сохраняет как черновик (статус **DRAFT**)
6. Может редактировать черновик сколько угодно
7. Нажимает «Отправить на модерацию» (статус **PENDING_MODERATION**)
8. После одобрения преподавателем статус меняется на **PUBLISHED**
9. Тест появляется в каталоге для всех студентов

**Жизненный цикл теста (State Machine):**
```
┌─────────────────────────────────────────────────────────────────┐
│                    СТАТУСЫ ТЕСТА                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  DRAFT ──[отправить]──> PENDING_MODERATION                     │
│    │                        │                                  │
│    │                        ├──[одобрить]──> PUBLISHED         │
│    │                        │                                  │
│    │                        └──[отклонить]──> DRAFT            │
│    │                                                           │
│    └──[удалить]──> ARCHIVED                                    │
│                                                                 │
│  PUBLISHED ──[архивировать]──> ARCHIVED                        │
│                                                                 │
│  ⛔ НЕВОЗМОЖНО: DRAFT → PUBLISHED (без модерации)              │
│  ⛔ НЕВОЗМОЖНО: ARCHIVED → PUBLISHED                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**Технические детали:**
- State Machine блокирует недопустимые переходы на уровне кода
- Все переходы статусов логируются
- Автор может редактировать тест только в статусе DRAFT

---

### 3.3. Модуль прохождения тестов

**Что происходит:**
1. Студент открывает каталог тестов
2. Фильтрует по предмету / сложности
3. Выбирает тест, нажимает «Начать»
4. Система создаёт попытку (TestAttempt) со статусом **IN_PROGRESS**
5. Студент видит вопросы (по одному или списком)
6. Выбирает варианты ответов
7. Нажимает «Завершить»
8. Система проверяет ответы, подсчитывает баллы
9. Статус попытки меняется на **COMPLETED**
10. Студент видит результат:
    - Набранные баллы / максимальные баллы
    - Процент правильных ответов
    - Какие вопросы ответил верно/неверно
    - Сколько баллов рейтинга получил
11. Система публикует событие **TestCompleted**
12. Observer обновляет рейтинг и проверяет достижения

**В Telegram:**
- Бот присылает вопросы по одному
- После каждого вопроса — следующий
- В конце — результат с кнопкой «Подробнее» (ссылка на веб)

**Технические детали:**
- Время начала и завершения фиксируется
- Можно добавить лимит времени на тест
- Попытки сохраняются в истории

---

### 3.4. Модуль рейтинга и достижений

**Что происходит после каждого теста:**

```
┌─────────────────────────────────────────────────────────────────┐
│                    ПОТОК ОБНОВЛЕНИЯ РЕЙТИНГА                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. Студент завершает тест                                     │
│         │                                                       │
│         ▼                                                       │
│  2. Система публикует событие TestCompleted                    │
│         │                                                       │
│    ┌────┼────┐                                                  │
│    ▼    ▼    ▼                                                  │
│  Рейтинг  Достижения  Уведомления                              │
│    │        │            │                                      │
│    ▼        ▼            ▼                                      │
│  +баллы   +бейдж     Telegram-сообщение                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**Система рейтинга:**
- Баллы начисляются по стратегии (Strategy Pattern)
- Стандартная формула: `баллы за тест × коэффициент сложности`
- Рейтинг хранится по предметам
- Таблица лидеров обновляется в реальном времени (Redis)

**Достижения (5 штук для MVP):**

| Код | Название | Условие |
|-----|----------|---------|
| FIRST_TEST | Первый тест | Пройти 1 тест |
| STREAK_3 | Серия побед | 3 теста подряд без ошибок |
| SUBJECT_MASTER | Эксперт предмета | Топ-3 в дисциплине |
| TEST_CREATOR | Создатель | Опубликовать 1 тест |
| PERFECT_SCORE | Идеальный результат | 100% правильных ответов |

**Технические детали:**
- Observer паттерн: модуль тестов не знает про модуль достижений
- Достижения проверяются асинхронно
- Уведомления отправляются в Telegram

### 3.5. Модуль статистики

**Что видит студент:**
- Количество пройденных тестов
- Средний балл
- Динамика рейтинга (график)
- Прогресс по предметам (какие темы знает лучше/хуже)
- История всех попыток с датами

**Что видит преподаватель:**
- Статистика группы (средний балл, активность)
- Прогресс конкретных студентов
- Какие тесты пользуются популярностью

**Технические детали:**
- Данные агрегируются из таблицы попыток
- Графики строятся на фронтенде (Chart.js)

### 3.6. Telegram-бот

**Команды:**

| Команда | Описание | Ответ бота |
|---------|----------|------------|
| `/start` | Приветствие | «Привет! Я SkillFlow Bot. Выбери действие:» + кнопки меню |
| `/tests` | Каталог тестов | Список предметов → список тестов → кнопка «Начать» |
| `/stats` | Личная статистика | «Ты прошёл 15 тестов, средний балл 85%, рейтинг: 1250» |
| `/rating` | Таблица лидеров | Топ-10 по выбранному предмету с позицией пользователя |
| `/achievements` | Мои достижения | Список бейджей с датами получения |
| `/profile` | Профиль | Email, группа, факультет, кнопка «Отвязать Telegram» |
| `/help` | Справка | Инструкция по использованию |

**Сценарий прохождения теста в боте:**
```
1. Пользователь: /tests
2. Бот: «Выбери предмет» + кнопки [Математика] [Физика] [Программирование]
3. Пользователь: нажимает [Программирование]
4. Бот: «Выбери тест» + кнопки [Тест по Python] [Тест по Java]
5. Пользователь: нажимает [Тест по Python]
6. Бот: «Начинаем тест! Вопрос 1 из 10...» + кнопки вариантов
7. Пользователь: выбирает вариант
8. Бот: «Вопрос 2 из 10...» + кнопки вариантов
9. ... (повторяется до конца)
10. Бот: «Тест завершён! Твой результат: 85/100. +50 баллов рейтинга»
11. Бот: Кнопка «Подробнее» → ссылка на веб-интерфейс
```

**Технические детали:**
- Adapter Pattern: бот преобразует сообщения Telegram в команды API
- FSM (Finite State Machine) для состояния прохождения теста
- Long Polling или Webhook для получения обновлений

## 5. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

### 5.1. Архитектура

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| **Backend** | Python 3.12 + FastAPI | Асинхронность, подготовка к AI (Фаза 3) |
| **Frontend** | JavaScript | Типизация, богатая экосистема |
| **Telegram Bot** | aiogram 3.x | Лучшая поддержка Telegram API |
| **База данных** | PostgreSQL 15 | Надёжность, связи между сущностями |
| **Кэш** | Redis 7 | Рейтинги в реальном времени |
| **Контейнеризация** | Docker + Docker Compose | Единая среда разработки |

### 5.2. Паттерны проектирования (6 штук)

| Паттерн | Где применяется | Кто реализует |
|---------|----------------|---------------|
| **Repository** | Доступ ко всем сущностям (User, Test, Attempt...) | Студент 1 |
| **State Machine** | Жизненный цикл теста (DRAFT → PUBLISHED) | Студент 1 |
| **Observer** | Событие TestCompleted → Rating + Achievement | Студент 2 |
| **Strategy** | Алгоритмы начисления баллов рейтинга | Студент 2 |
| **Factory Method** | Создание вопросов разных типов | Студент 3 |
| **Adapter** | Интеграция Telegram-бота с API | Студент 3 |

```
│  7. Видит: «+45 баллов рейтинга»                               │
│  8. Система проверяет достижения                               │
│  9. Если условие выполнено → «Достижение разблокировано!»      │
│  10. Telegram-бот присылает уведомление                        │
│  11. Рейтинг в таблице лидеров обновляется                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## 7. МОДЕЛЬ ДАННЫХ (УПРОЩЁННАЯ)

```sql
-- Пользователи
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    telegram_id VARCHAR(50) UNIQUE,
    role VARCHAR(20) NOT NULL DEFAULT 'STUDENT',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE students (
    id INTEGER PRIMARY KEY REFERENCES users(id),
    group_id INTEGER NOT NULL,
    faculty VARCHAR(100) NOT NULL,
    course INTEGER NOT NULL,
    rating_score INTEGER DEFAULT 0
);

CREATE TABLE teachers (
    id INTEGER PRIMARY KEY REFERENCES users(id),
    department VARCHAR(100) NOT NULL
);

-- Предметы
CREATE TABLE subjects (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    code VARCHAR(20) UNIQUE NOT NULL
);

-- Тесты
CREATE TABLE tests (
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    subject_id INTEGER REFERENCES subjects(id),
    difficulty INTEGER NOT NULL CHECK (difficulty BETWEEN 1 AND 5),
    status VARCHAR(20) NOT NULL DEFAULT 'DRAFT',
    author_id INTEGER REFERENCES students(id),
    moderator_id INTEGER REFERENCES teachers(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    published_at TIMESTAMP
);

-- Вопросы
CREATE TABLE questions (
    id SERIAL PRIMARY KEY,
    test_id INTEGER REFERENCES tests(id) ON DELETE CASCADE,
    text TEXT NOT NULL,
    points INTEGER NOT NULL DEFAULT 1,
    question_type VARCHAR(20) NOT NULL
);

-- Варианты ответов
CREATE TABLE answer_options (
    id SERIAL PRIMARY KEY,
    question_id INTEGER REFERENCES questions(id) ON DELETE CASCADE,
    text TEXT NOT NULL,
    is_correct BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order INTEGER NOT NULL
);

-- Попытки прохождения
CREATE TABLE test_attempts (
    id SERIAL PRIMARY KEY,
    test_id INTEGER REFERENCES tests(id),
    student_id INTEGER REFERENCES students(id),
    started_at TIMESTAMP NOT NULL,
    completed_at TIMESTAMP,
    score INTEGER NOT NULL DEFAULT 0,
    max_score INTEGER NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'IN_PROGRESS'
);

-- Ответы пользователя
CREATE TABLE user_answers (
    id SERIAL PRIMARY KEY,
    attempt_id INTEGER REFERENCES test_attempts(id) ON DELETE CASCADE,
    question_id INTEGER REFERENCES questions(id),
    selected_option_ids INTEGER[],
    is_correct BOOLEAN,
    points_earned INTEGER DEFAULT 0
);

-- Рейтинги
CREATE TABLE ratings (
    id SERIAL PRIMARY KEY,
    student_id INTEGER REFERENCES students(id),
    subject_id INTEGER REFERENCES subjects(id),
    total_score INTEGER NOT NULL DEFAULT 0,
    position INTEGER,
    last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(student_id, subject_id)
);

-- Достижения
CREATE TABLE achievements (
    id SERIAL PRIMARY KEY,
    code VARCHAR(50) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    icon_url VARCHAR(255)
);

-- Полученные достижения
CREATE TABLE user_achievements (
    id SERIAL PRIMARY KEY,
    student_id INTEGER REFERENCES students(id),
    achievement_id INTEGER REFERENCES achievements(id),
    earned_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(student_id, achievement_id)
);
```
