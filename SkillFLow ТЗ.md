## 1. ОБЩИЕ СВЕДЕНИЯ

### 1.1. Наименование проекта
**SkillFlow** — локальная студенческая соревновательная тестовая платформа.

### 1.2. Заказчик и разработчик
| Роль | Описание |
|------|----------|
| **Заказчик** | Государственный университет (образовательная среда) |
| **Разработчик** | Команда разработки (3 человека) |
| **Пользователи** | Студенты 1-4 курса, преподаватели, кураторы |

### 1.3. Область применения
Образовательная среда государственного вуза для повышения вовлечённости студентов в самостоятельную подготовку через геймификацию и соревновательный элемент.

### 1.4. Нормативные документы
- Федеральный закон «Об образовании в РФ» № 273-ФЗ
- Требования к защите персональных данных (152-ФЗ)
- Внутренние стандарты вуза по информационным системам

## 2. НАЗНАЧЕНИЕ И ЦЕЛИ РАЗРАБОТКИ

### 2.1. Назначение системы
SkillFlow предназначена для:
1. Создания учебных тестов студентами
2. Прохождения тестов другими студентами
3. Формирования рейтинговой системы по дисциплинам
4. Отслеживания прогресса и достижений
5. Предоставления доступа через веб-интерфейс и Telegram-бот

### 2.2. Цели разработки
| Цель | Критерий достижения |
|------|---------------------|
| Повышение вовлечённости | ≥50% активных студентов группы используют систему еженедельно |
| Мотивация через геймификацию | ≥70% пользователей имеют минимум 1 достижение |
| Доступность | Система доступна 24/7 с uptime ≥99% |
| Удобство использования | Время на прохождение теста ≤5 минут |

### 2.3. Задачи проекта
1. Разработать веб-интерфейс для студентов и преподавателей
2. Разработать Telegram-бот для мобильного доступа
3. Реализовать централизованный backend с API
4. Внедрить систему рейтингов и достижений
5. Обеспечить модерацию пользовательского контента

| `/help` | Справка | Инструкция по использованию |

**Сценарий прохождения теста в боте:**
```
1. Пользователь нажимает /tests
2. Бот показывает список предметов (inline keyboard)
3. Пользователь выбирает предмет
4. Бот показывает список тестов по предмету
5. Пользователь выбирает тест → нажимает «Начать»
6. Бот присылает вопросы по одному с кнопками вариантов
7. После последнего вопроса → результат + баллы + изменение рейтинга
8. Кнопка «Подробнее» → ссылка на веб-интерфейс
```

**Технические требования:**
- Библиотека: aiogram 3.x
- Язык: Python 3.11+
- Тип бота: Long Polling или Webhook
- Поддержка inline keyboard и callback queries

### 4.2. Модульная структура

| Модуль | Компоненты | Ответственный |
|--------|------------|---------------|
| **core** | User, Student, Teacher, Auth, DI | Разработчик 1 |
| **content** | Test, Question, AnswerOption, Subject, State Machine | Разработчик 1 |
| **execution** | TestAttempt, UserAnswer, Validation | Разработчик 2 |
| **gamification** | Rating, Achievement, UserAchievement, Observer | Разработчик 2 |
| **api** | Controllers, DTO, Middleware, Swagger | Разработчик 2 |
| **frontend** | React Components, Pages, Store | Разработчик 3 |
| **bot** | Handlers, Keyboards, API Client | Разработчик 3 |

### 4.3. Паттерны проектирования

| Паттерн | Место применения | Обоснование |
|---------|------------------|-------------|
| **Repository** | Доступ ко всем сущностям | Тестируемость, абстракция БД |
| **Service Layer** | Бизнес-логика | Организация кода, разделение ответственности |
| **State Machine** | Жизненный цикл теста (Test) | Защита от некорректных переходов статусов |
| **Observer** | События (TestCompleted → Rating + Achievement) | Слабая связанность модулей |
| **DTO** | API запросы/ответы | Валидация, чёткие контракты |
| **Dependency Injection** | Внедрение зависимостей в сервисы | Тестируемость, гибкость |

## 5. МОДЕЛЬ ДАННЫХ

### 5.1. Схема базы данных

```sql
-- Пользователи
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    telegram_id VARCHAR(50) UNIQUE,
    role VARCHAR(20) NOT NULL DEFAULT 'STUDENT',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE students (
    id INTEGER PRIMARY KEY REFERENCES users(id),
    group_id INTEGER NOT NULL,
    faculty VARCHAR(100) NOT NULL,
    course INTEGER NOT NULL,
    rating_score INTEGER DEFAULT 0
);

CREATE TABLE teachers (
    id INTEGER PRIMARY KEY REFERENCES users(id),
    department VARCHAR(100) NOT NULL
);

-- Предметы
CREATE TABLE subjects (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    code VARCHAR(20) UNIQUE NOT NULL,
    department_id INTEGER
);

-- Тесты
CREATE TABLE tests (
    id SERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    subject_id INTEGER REFERENCES subjects(id),
    difficulty INTEGER NOT NULL CHECK (difficulty BETWEEN 1 AND 5),
    status VARCHAR(20) NOT NULL DEFAULT 'DRAFT',
    author_id INTEGER REFERENCES students(id),
    time_limit INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    published_at TIMESTAMP
);

-- Вопросы
CREATE TABLE questions (
    id SERIAL PRIMARY KEY,
    test_id INTEGER REFERENCES tests(id) ON DELETE CASCADE,
    text TEXT NOT NULL,
    points INTEGER NOT NULL DEFAULT 1,
    question_type VARCHAR(20) NOT NULL
);

-- Варианты ответов
CREATE TABLE answer_options (
    id SERIAL PRIMARY KEY,
    question_id INTEGER REFERENCES questions(id) ON DELETE CASCADE,
    text TEXT NOT NULL,
    is_correct BOOLEAN NOT NULL DEFAULT FALSE,
    sort_order INTEGER NOT NULL
);

-- Попытки прохождения
CREATE TABLE test_attempts (
    id SERIAL PRIMARY KEY,
    test_id INTEGER REFERENCES tests(id),
    student_id INTEGER REFERENCES students(id),
    started_at TIMESTAMP NOT NULL,
    completed_at TIMESTAMP,
    score INTEGER NOT NULL DEFAULT 0,
    max_score INTEGER NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'IN_PROGRESS'
);

-- Ответы пользователя
CREATE TABLE user_answers (
    id SERIAL PRIMARY KEY,
    attempt_id INTEGER REFERENCES test_attempts(id) ON DELETE CASCADE,
    question_id INTEGER REFERENCES questions(id),
    selected_option_ids INTEGER[],
    text_answer TEXT,
    is_correct BOOLEAN,
    points_earned INTEGER DEFAULT 0
);

-- Рейтинги
CREATE TABLE ratings (
    id SERIAL PRIMARY KEY,
    student_id INTEGER REFERENCES students(id),
    subject_id INTEGER REFERENCES subjects(id),
    total_score INTEGER NOT NULL DEFAULT 0,
    position INTEGER,
    last_updated TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(student_id, subject_id)
);

-- Достижения
CREATE TABLE achievements (
    id SERIAL PRIMARY KEY,
    code VARCHAR(50) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    description TEXT,
    icon_url VARCHAR(255),
    points_required INTEGER
);

-- Полученные достижения
CREATE TABLE user_achievements (
    id SERIAL PRIMARY KEY,
    student_id INTEGER REFERENCES students(id),
    achievement_id INTEGER REFERENCES achievements(id),
    earned_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    is_notified BOOLEAN DEFAULT FALSE,
    UNIQUE(student_id, achievement_id)
);
```

### 5.2. Redis структура

| Ключ | Тип | Описание | TTL |
|------|-----|----------|-----|
| `session:{user_id}` | String | JWT сессия | 24 часа |
| `rating:subject:{subject_id}` | Sorted Set | Таблица лидеров по предмету | Бессрочно |
| `rating:global` | Sorted Set | Общий рейтинг | Бессрочно |
| `test:attempt:{attempt_id}` | Hash | Временные данные попытки | 1 час |
| `cache:test:{test_id}` | String | Кэш данных теста | 10 минут |

## 6. API СПЕЦИФИКАЦИЯ

### 6.1. Аутентификация

| Endpoint | Method | Request | Response | Описание |
|----------|--------|---------|----------|----------|
| `/api/auth/register` | POST | `{email, password, faculty, group, course}` | `{user_id, token}` | Регистрация студента |
| `/api/auth/login` | POST | `{email, password}` | `{user_id, token}` | Вход |
| `/api/auth/telegram-link` | POST | `{telegram_code}` | `{success}` | Привязка Telegram |
| `/api/auth/refresh` | POST | `{refresh_token}` | `{token}` | Обновление токена |

### 6.2. Тесты

| Endpoint | Method | Request | Response | Описание |
|----------|--------|---------|----------|----------|
| `/api/tests` | GET | `?subject_id=&difficulty=&page=` | `TestResponse[]` | Каталог тестов |
| `/api/tests/{id}` | GET | - | `TestDetailResponse` | Детали теста |
| `/api/tests` | POST | `CreateTestRequest` | `TestResponse` | Создание теста |
| `/api/tests/{id}` | PUT | `UpdateTestRequest` | `TestResponse` | Редактирование теста |
| `/api/tests/{id}/publish` | POST | - | `TestResponse` | Отправка на модерацию |
| `/api/tests/{id}/moderate` | POST | `{action: approve/reject}` | `TestResponse` | Модерация (преподаватель) |

### 6.3. Прохождение тестов

| Endpoint | Method | Request | Response | Описание |
|----------|--------|---------|----------|----------|
| `/api/attempts` | POST | `{test_id}` | `{attempt_id}` | Начало попытки |
| `/api/attempts/{id}/submit` | POST | `{answers: []}` | `AttemptResponse` | Завершение попытки |
| `/api/attempts/{id}` | GET | - | `AttemptDetailResponse` | Детали попытки |
